# Feature Specification：全站 UI 与交互统一

Feature ID：001-ui-experience-unification

创建：2026-10-18 · 版本：1.0.0 · 状态：Approved for technical planning

2026-10-18 用户确认本规范及所列修正建议，授权细化方案与任务；明确“先不编码，方案完成后给我确认”。业务要求未变更。

输入：统一短剧工厂 UI 和交互，以尽量少的操作得到成片；按第一性原理、高内聚低耦合设计；本轮使用 Spec Kit，先明确需求与验收，再制定技术方案和任务，未经确认不进入大规模编码。

## 1. 目标与范围

客户在同一工作台中知道“现在做到哪里、是否需要我操作、完成后在哪里获取”，无需理解内部生成链路。已有用户习惯、商业规则与恢复能力必须保持。

范围覆盖登录/注册、我的项目、新建短片、项目详情与下载、积分充值与记录、账户安全、推广工作台、管理后台及上述页面的公共加载/异常状态。页面范围以本次核对路由为准，见下表。

| 用户区域 | 当前路径 / 页面 | 本轮边界 |
| --- | --- | --- |
| 访客 | /login、/register、/p/:code | 统一品牌、字段、反馈；保留登录注册与推广归属规则 |
| 创作者 | /、新建面板、/project/:id | 项目优先、直接开始、过程可理解、成片可获取 |
| 账户与资金 | /credits、/settings、/security | 充值独立、账户安全内聚；保持旧链接兼容 |
| 推广 | /partner、/partner/customers、/partner/orders、/partner/settings | 统一列表详情，不开启新的分佣 |
| 管理员 | /admin/stats、/admin/jobs、/admin/orders、/admin/users、/admin/partners、/admin/system | 统一外观与操作反馈，保持既有权限、业务动作与记录 |

范围外：重写前后端、改商业模型、新模板市场/社区、手工生成模式、新支付渠道、真实交易或生成测试、生产部署。当前未知路径跳转规则不在本轮改动范围。

## 2. 已有证据

基线 `6b902ed`；前次隔离浏览器证据在 README 链接的 capture.json 与截图目录。本轮复读源码和路由，未重复执行浏览器采集。

- U01：首页长摘要在 375px 横向撑宽；需建立失败→通过的布局回归。
- U02：项目阶段“分镜/审片”共用排序值，出现双高亮；需建立失败→通过的状态回归。
- U03–U05：创作与管理样式分裂、设置嵌套整页充值/安全、页头和字段层级不一致。
- U06–U08：项目结果优先级弱、表格/弹层风格分裂、充值缺少完整原执行上下文。

以上是现有呈现和结构证据，不证明后端续跑失败，也不代表本次改版已验证。

## 3. 用户故事与独立验收场景

### US1 · 找到并继续项目（P1）

作为创作者，我进入工作台优先看到自己的项目与需处理事项，能快速回到原工作位置。

独立验证：有项目、空列表和长文本的合成账户，不需要付费生成。

1. Given 已有项目，When 登录进入，Then “我的项目”是主视图；与角色无关的入口不出现。
2. Given 375px 屏幕和长标题，When 浏览列表，Then 内容不撑宽页面，状态与主要操作可见。
3. Given 筛选后打开项目，When 返回列表，Then 保留筛选和可恢复的浏览位置；账户切换不保留上一账号数据。

### US2 · 一次提交开始自动创作（P1）

作为创作者，我输入想法并看清生成范围后点击开始，不需要逐阶段确认。

独立验证：模拟费用估算、项目创建、原 run 启动，不连接收费上游。

1. Given 需求有效且积分足够，When 点击一次开始，Then 进入同一执行的制作视图，无预算确认或人工审片门禁。
2. Given 积分不足，When 已提交创作，Then 保存并展示原执行的充值上下文，不循环创建项目或执行。
3. Given 启动响应丢失，When 用户重试查询，Then 先核对原执行，不能创建第二笔消费。

### US3 · 理解真实进度并取得成片（P1）

作为创作者，我优先看到当前进展和可用作品，技术过程按需展开。

独立验证：各阶段、各执行状态及作品可用性组合，不实际生成。

1. Given 正在制作，When 打开项目，Then 当前阶段只有一个高亮，执行状态单独解释，计数有事实依据。
2. Given 执行结束且成片可用，When 查看项目，Then 预览与下载位于主要内容区首屏。
3. Given 上游结果未知或正在对账，When 查看项目，Then 保留原任务信息，不提供无依据的重新生成按钮。

### US4 · 充值后接回原执行（P1）

作为创作者，我希望到账后原任务按规则继续，并能看懂延迟和例外。

独立验证：隔离库与模拟支付通知、入账、恢复队列；不用真实订单。

1. Given 原 run 等待积分，When 付款、入账、恢复依次被服务端确认，Then 界面依次反映事实，原 run_id 不变。
2. Given 仅付款确认，When 入账或续跑仍未完成，Then 不显示“已继续”或“制作成功”。
3. Given 已取消、越权、停用或未知结果的执行，When 到账，Then 不擅自复活/重发执行；余额与到账信息仍按授权事实显示。

### US5 · 在统一规则中管理账户和业务（P2）

作为普通用户、推广者或管理员，我希望相同操作的布局、反馈与导航一致，同时各自业务明确。

独立验证：访客/普通/推广/管理员及权限撤销的模拟会话。

1. Given 账户设置，When 刷新或后退，Then 保持合法的当前页面，不重置到无关内容；充值拥有独立页面身份。
2. Given 推广或管理员权限，When 进入相应空间，Then 账户入口位置一致，列表和详情使用一致操作习惯。
3. Given 权限失效或切换账号，When 旧请求返回，Then 不展示旧身份数据，禁止基于旧权限继续操作。

### US6 · 小屏、弱网和键盘操作仍可完成任务（P2）

独立验证：375/768/1440px、缩放、键盘、慢响应、断线、切后台。

1. Given 窄屏或 200% 缩放，When 浏览与输入，Then 核心内容重排，主操作可到达，字段错误就地可读。
2. Given 请求失败，When 重试查询，Then 只重查数据，不触发收费动作；重要错误不自行消失造成无从处理。
3. Given 页面隐藏后恢复，When 页面重新可见，Then 重查当前事实，不补发累计轮询或生成请求。

## 4. 业务不变量

| ID | 必须保持的规则 |
| --- | --- |
| BR-001 | 保留当前价格、积分、预占/扣减/返还、退款、分佣与归属规则，不在文档中重设数值 |
| BR-002 | 积分足够直接生成，不足提示充值后按既有规则续跑；无预算确认、无人工阶段门禁 |
| BR-003 | 付款确认、积分入账、原 run 恢复分别依据服务端可核实事实；前端不得推断其中任一步已成功 |
| BR-004 | run_id/项目/账号必须一致；重复点击、通知、刷新、多标签不得产生重复收费或第二个替代执行 |
| BR-005 | 未知提交保留任务与预占并查证；已取消、已完成、无权访问的执行不因到账而被重新生成 |
| BR-006 | 页面离开和账号切换不改变服务端合法执行；旧身份数据、异步响应及草稿不能泄露到新身份 |
| BR-007 | 测试不使用生产数据，不做真实付款、退款或生成；上线仍需独立审批 |

## 5. 功能要求

| ID | 可验证要求 | 故事 |
| --- | --- | --- |
| FR-001 | “我的项目”作为创作主入口；次要空间入口集中在用户名附近，位置与命名一致；同一功能只维护一套流程 | US1、US5 |
| FR-002 | 各页面具有一个清晰主标题、必要说明和主动作；正文、表单、状态、加载/空态/错误层级全站一致 | US1、US5、US6 |
| FR-003 | 无项目时显示同一创作入口；有项目时项目与需处理状态优先，不被大型欢迎区遮挡 | US1 |
| FR-004 | 新建默认突出想法、画幅、时长；其他既有选择可展开；保留当前默认值与生成范围 | US2 |
| FR-005 | 提交前显示服务端可核实的费用范围；估算失败不得伪装为免费或擅自使用前端固定费用；不新增确认步骤 | US2 |
| FR-006 | 草稿在同账号本次登录会话关闭重开面板可恢复，主动退出/切账号清理；不承诺跨设备或退出后恢复 | US2、US5 |
| FR-007 | 一次开始对应原执行；处理中有反馈；超时/未知结果先查证，不以新建项目或 run 替代恢复 | US2、US4 |
| FR-008 | 项目首先显示结果/进度与下一步；剧本、角色、镜头等按需展开，不增加人工通过步骤 | US3 |
| FR-009 | 制作阶段与执行状态分开表达；运行中仅一个当前阶段，完成态无伪造的“正在进行”；计数不可捏造 | US3 |
| FR-010 | 缺积分、结算待核对、未知提交、失败、已停止、已完成、离线各有真实说明与允许动作；“重试查询”与“继续生成”明确区分 | US3、US4、US6 |
| FR-011 | 有效 run_id 充值上下文展示项目与执行；无 run_id 按普通充值；无权访问不披露原项目，非法参数不得绑定另一执行 | US4 |
| FR-012 | 到账后余额、充值订单、原 run、项目列表按事实刷新；只对仍处于该充值流程的同账号用户返回原项目，离开者不强制跳转 | US4 |
| FR-013 | 充值不足、取消/完成、停用、权限变化、迟到通知及多标签均按既有恢复规则解释；界面查询无新建执行副作用 | US4 |
| FR-014 | 账户设置内不再嵌套整页充值或运营页面；旧合法直链兼容，刷新/后退保留授权上下文，返回地址不允许外部跳转 | US5 |
| FR-015 | 普通、推广、管理员的页面/动作保留既有鉴权；隐藏入口不替代后端校验，推广页不显示未开启的分佣收益 | US5 |
| FR-016 | 所有目标页面在 375/768/1440px 可用，长内容不撑宽文档；弹层焦点、关闭返回、键盘操作、表单错误与重要失败反馈一致 | US6 |
| FR-017 | 页面隐藏暂停无价值查询，恢复可见核对最新状态；无请求堆积、重复订阅和离屏视频自动下载 | US6 |
| FR-018 | 每条要求关联验收与测试证据；实现前做一致性审查，完工后逐项收敛并独立复审；未测不能标通过 | 全部 |

## 6. 关键对象与边界条件

关键对象：账户/权限、项目、创作执行、镜头或生成任务、成片/版本、充值订单、积分账本、推广归属。此处不新建实体或表；技术方案再确认现有字段与接口。

必须覆盖：空/超长文本、空数据/分页末页、无积分、估算失败、重复点击、提交响应丢失、旧会话晚到、撤销权限、错误/越权 run_id、普通充值、积分不足以恢复、重复/乱序通知、入账延迟、已停止/已完成任务、未知提交、结算延迟、多个待继续执行、多标签、下载过期或失败、离线与隐藏页面恢复。

## 7. 成功标准

| ID | 量化标准 |
| --- | --- |
| SC-001 | FR-001–FR-018 与 AC-001–AC-024 全部有追踪；必要项未验证或失败不能宣布交付完成 |
| SC-002 | 所有目标路由在三档尺寸及长内容/空态/错误态下无文档级横向溢出；仅明确标识的媒体/数据视口可独立滚动 |
| SC-003 | 有效输入且积分足够时，一次“开始生成”进入原执行，新增预算确认与人工阶段确认次数为 0 |
| SC-004 | 所有资金与恢复回归中，因界面刷新/重复通知新增的 run 和重复扣费均为 0；业务数值与边界测试保持一致 |
| SC-005 | 账号切换/停用/权限变化场景中，旧身份数据闪现、草稿泄漏、越权操作成功均为 0 |
| SC-006 | 全部目标页面主标题、主次动作、字段与反馈符合统一契约；手机触控主要动作不小于 44px，键盘可完成核心操作 |
| SC-007 | 同设备、同构建模式、同合成数据至少 5 次采样，比较中位 LCP 与固定核心操作响应延迟；回退同时超过 10% 和 100ms 即不通过。对应路由初始 JavaScript gzip 体积增长同时超过 10% 和 10KiB 也不通过；不得新增重复轮询/订阅 |

上述性能回退容差随本规范获确认；plan 阶段固定场景，执行阶段测量基线及优化结果，不得事先声称提速，也不能用减少页面功能满足体积指标。测试中的操作延迟不冒充真实用户 INP。技术门槛、未验证项目与原始证据记录方式见 acceptance.md。
