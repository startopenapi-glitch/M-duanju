# Clarifications：手动逐阶段制作

状态：Confirmed（2026-10-19 用户选择）· 仍需确认最终 spec/plan 后才实施

## C-01 · 章程冲突（已选择）

旧 constitution 1.0.0 明确禁止“手动生成模式/逐阶段确认”，用户本次要求相反。

**决定：** 采用 [constitution-amendment.md](constitution-amendment.md) 的 2.0.0 方向：**全站立即手动，旧自动 run 只保留历史/核对兼容，不再自动推进。**

## C-02 · 手动模式范围（已选择）

**全站立即手动：**

- 新项目创建即 manual；
- 存量项目全部切换 manual；
- 旧自动 run 不再自动派发下一阶段；
- 已完成项目只读/可发起修改；
- 失败或卡住项目进入对应手动阶段，由用户继续。

## C-03 · 进行中自动 run 的安全停止（已选择方向）

用户选择“全站立即手动”。为不重复扣费/不丢失已付费结果，采用以下安全语义：

1. 立即停止**派发新阶段**；
2. 已提交上游、正在轮询或 `reconcile` 的 job **继续核对和结算**；
3. 尚未提交、仍在排队的 job 取消并释放预占；
4. 不退款、不撤回已结算费用；
5. 已提交任务完成后，项目停留在对应阶段，等待用户按手动流程确认；
6. 不把“停止”伪装成“退款/取消上游”。

**仍需确认：** 是否接受“已提交任务继续结算”的安全停止，而不是硬杀所有上游。

## C-04 · 镜头确认粒度（已选择）

**逐镜头通过**；全部镜头 `APPROVED` 且有视频后才允许合成。取消通过/重做可能再次计费，必须二次确认。

## C-05 · 成片确认（已选择）

**不新增最终确认状态。** 合成成功即 `COMPLETED`，成片页提供预览/下载，不再增加付费动作。

## C-06 · 自动入口（已选择）

**新项目不提供全自动入口**；旧 `generation_runs` 与 orchestrator 代码保留用于历史/对账，不用于新项目推进。

## C-07 · 导航形态（建议，待最终确认）

采用独立 URL：

- `/project/:id/script`
- `/project/:id/keyvisual`
- `/project/:id/shots`
- `/project/:id/final`
- `/project/:id` 重定向到当前合法阶段

阶段条可点击；未来阶段锁定；刷新/后退保留。

## C-08 · 失败/余额/未知任务（建议，待最终确认）

- 阶段失败：停在该阶段，可重试；不自动下一阶段；
- 余额不足：不创建任务，显示缺口，充值后由用户回来确认；
- `submission_unknown/reconcile`：不允许确认绕过，必须核对；
- 重做已通过镜头：二次确认，可能再次扣费。
