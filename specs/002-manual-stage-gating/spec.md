# Feature Specification：手动逐阶段制作

Feature ID：002-manual-stage-gating  
创建：2026-10-19 · 版本：0.1.0 · 状态：T01–T08 implemented；2026-10-19 已部署；unknown 已释放  
输入：用户要求“全自动有问题，切成手动；导航可点击进入剧本、定妆照、镜头、成片；上一环节确认后，后面再执行；先策划再确认，不直接大规模编码”。

## 1. 目标

把“一次点击自动跑到成片”改为**以阶段为单位的可控制作**：

1. 新建项目默认进入手动模式；
2. 用户可从阶段导航进入剧本、定妆照、镜头、成片；
3. 每个阶段完成后停住，只有用户明确确认，才发生下一阶段的付费生成或合成；
4. 用户可以回看已完成阶段，但不能无确认跳过门禁；
5. 不改变现有价格、积分、预占/结算、退款、归属和审计规则。

## 2. 非目标

- 不重写生成 Provider、支付、结算或现有自动执行的财务逻辑；
- 不改变 1 元=100 积分、单段/定妆照价格或当前充值赠送；
- 不物理删除旧自动 run 或历史项目；
- 不新增模板市场、社区、分销佣金或新支付渠道；
- 不在本规格阶段编码、迁移数据或部署。

## 3. 用户故事

### US1 · 新建手动项目
作为创作者，我新建项目后只看到剧本入口，不会自动扣费生成定妆照或镜头。

### US2 · 剧本确认
作为创作者，我生成/编辑剧本并检查角色、场景、镜头，确认后才生成定妆照。

### US3 · 定妆照确认
作为创作者，我查看定妆照，确认后才生成镜头。

### US4 · 镜头确认
作为创作者，我逐条查看镜头视频，通过/重做；全部通过后才可合成。

### US5 · 成片
作为创作者，我查看合成结果、下载成片；不因打开页面自动触发任何付费动作。

### US6 · 阶段导航
作为创作者，我可以点击阶段导航进入已完成/当前阶段；未来阶段显示锁定，不能通过 URL 绕过。

### US7 · 旧自动执行的历史兼容
作为已有用户，我原先的全自动执行不会被静默删除或重复扣费；停止后我能在对应阶段接手，而不是继续自动推进。

## 4. 业务规则

| ID | 规则 |
| --- | --- |
| BR-001 | **全站所有项目切换 `workflow_mode=manual`**；新项目不再创建自动 run；旧自动 run 只保留历史/核对兼容，不再自动推进下一阶段。 |
| BR-002 | 手动项目**不创建 generation_run**；阶段由项目状态 + jobs + 用户确认推进。 |
| BR-003 | 剧本阶段免费；确认剧本后才允许创建定妆照任务（当前 30 积分规则不变）。 |
| BR-004 | 确认定妆照后才允许创建镜头任务；每个镜头按现有单段价格预占/结算。 |
| BR-005 | 每个镜头可单独通过/取消通过/重做；所有镜头通过后才允许合成。 |
| BR-006 | 合成成功后才显示成片；最终是否增加“确认成片”见 C-05，默认不新增付费动作。 |
| BR-007 | “确认”必须是显式按钮 + 服务端持久化事实；刷新、轮询、打开页面、自动重试不得被当成确认。 |
| BR-008 | 同一阶段重复点击/并发请求不得重复创建付费任务；使用项目锁和幂等约束。 |
| BR-009 | 上游失败/提交未知时保留原任务和预占；未知提交不得自动重发，必须人工核对。 |
| BR-010 | 所有阶段仍校验项目所有者、账号状态、项目状态和金额；前端隐藏按钮不能替代后端校验。 |
| BR-011 | 阶段导航只能进入已完成/当前阶段；未来阶段不可进入，直接 URL 返回锁定/当前阶段。 |
| BR-012 | 不修改现有价格、积分、退款、分佣、审计和归属规则。 |
| BR-013 | 全站切换时，立即停止派发新阶段；已提交/轮询/`reconcile` 的上游任务继续核对与结算；未提交的排队任务取消并释放预占；不退款、不硬杀已付费上游。 |

| AC-002 | 剧本未确认时直接调用定妆照/镜头/合成接口均被拒绝，状态和任务不变。 |

| AC-011 | 全站切换后无新的自动阶段派发；已提交任务继续核对/结算；未提交 queued job 取消并释放预占；旧 run 记录保留。 |

## 7. 关键边界

- 首次确认定妆照后任务异步，页面可离开；回来仍停在定妆照阶段，不自动进入镜头。
- 镜头生成中可逐条查看；未完成的镜头不能“全部通过”。
- 重做已通过镜头需要明确取消通过/重做，可能再次扣费，需确认。
- 余额不足：任务不创建或进入等待；充值后由用户回到该阶段再确认，不自动跨阶段。
- 上游 unknown：保持 reconcile，不允许“确认”绕过。
- 旧自动项目切换手动：只切换后续推进方式，不撤回已发生费用/素材。
- 删除/归档：沿用现有历史项目删除规则，不因本功能改变。

## 8. 成功标准

| ID | 标准 |
| --- | --- |
| SC-001 | 手动项目从创建到成片至少经过 4 次显式用户确认（剧本、定妆照、全部镜头、合成；C-05 可调整），无自动跨阶段。 |
| SC-002 | 确认前下一阶段任务数、预占数、扣费数均为 0；确认后重复请求新增任务数为 0。 |
| SC-003 | 新项目自动创建 run 数为 0；全站切换后新自动阶段派发数为 0；已提交任务仍可结算，未提交 queued job 新增扣费为 0。 |
| SC-004 | 所有阶段路由锁定、权限、失败/未知/余额不足用例有测试证据；未验证为 0。 |
| SC-005 | 价格、积分、退款、分佣相关回归与基线一致，新增业务规则变更数为 0。 |
