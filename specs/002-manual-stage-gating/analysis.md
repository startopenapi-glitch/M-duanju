# Consistency analysis（草案）

## 已解决（T01–T02）

- 章程 2.0.0 已写入；全站手动与安全停止边界已确认；
- workflow_mode 迁移与读取字段已实现；
- 安全停止命令复用 CancelRun，未提交 queued 取消、已提交任务保留；测试通过。

## T03–T06 已完成

- 后端确认接口、手动 stage 入口保护、HTTP 自动 run 拒绝；
- 四阶段路由、导航锁定；
- 剧本生成/编辑/确认、定妆照确认/重做、逐镜头通过/取消/重做、合成；
- 前端 146 测试通过；未部署。
- 角色、场景、镜头字段编辑已接入；仅 SCRIPT_REVIEW 可保存。

## 原分析

- 规格明确“全站手动、旧执行安全停止”；
- 业务规则不改变价格/积分/退款/分佣；
- 验收覆盖确认前无任务、重复确认、旧 run、权限、移动端；
- 技术方案复用现有 jobs/状态，避免重写执行器。

## 未解决/需确认

1. 章程冲突（C-01）：用户已选择全站立即手动，待最终确认章程 2.0.0 与安全停止语义。
2. 安全停止：已提交任务继续结算、未提交 queued 取消；需确认而非硬杀。
3. `ApproveKeyVisual` 现状为 no-op；需修正或新增 confirm，实施前定。
4. 手动 jobs 在 `run_id` 为空时的领取/结算/恢复需在 T03 回归。
5. 成片是否新增最终确认（C-05），影响状态机/验收数量。
6. 逐镜头 vs 整组（C-04），影响 UI/API/测试。
7. 自动入口是否完全移除（C-06）。
8. 阶段 URL 是否采用子路由（C-07）。

## 风险

- 若直接沿用自动 run 做手动门禁，worker 会继续推进；必须不创建 run 或显式停止。
- 若确认接口不幂等，重复点击会重复扣费。
- 若旧 `/keyvisual/approve` 保持 no-op，用户会“确认了但没进入镜头”。
- 若只做前端隐藏按钮，绕过 URL/API 会跳过门禁；后端必须强制。
